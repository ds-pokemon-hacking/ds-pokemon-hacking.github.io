## Field Sprites

### Overworld Sprites

An overworld ID identifies the graphics used by a map object (or "actor"). Look up the ID in the standard sprite or 3D object tables below. If the event uses a variable-driven ID (**101-116**), resolve it first.

#### Dynamic overworld IDs

Event IDs **101-116** read scripting (graphics) variables **`0x4020`-`0x402F`** in order. The variable holds the actual overworld ID. Look up that ID in the standard or 3D object table below. For a standard sprite, the resolved ID selects its texture, model, and animation timing.  
For example, player-gender checks in various scripts set `0x4020` to overworld ID **`0`** (Ethan, sprite `1_69`) or overworld ID **`97`** (Lyra, sprite `1_70`).

The resolver also accepts **117**, but it is unusable in the vanilla ROM.

:::info[Camera focus overworld]
Overworld ID `8192` (`0x2000`) is an invisible camera anchor. `ScrCmd_102` creates it at the supplied tile and switches camera and map tracking to it. `ScrCmd_103` removes it and restores tracking to the player.
:::

#### Standard overworld sprites

**Location**: `/a/0/8/1`

Standard overworld sprites use an NSBTX for textures and palettes, an NSBMD model to draw them on, and animation timing data to select frames.

##### Sprite textures (NSBTX)

For example, Cheryl's overworld ID `141` uses `1_62`, member `62` of `/a/0/8/1`.

Each row lists one graphics file and the overworld IDs that use it. Trainer class IDs are listed separately for the Battle Frontier and eyes-met trainer objects in map event files.

##### Overworld animation timing

The overworld graphics settings select an NSBMD model slot and an animation timing slot. The timing file determines which texture and palette from the overworld's NSBTX will display as the animation advances.

Each timing file starts with a 32-bit entry count, followed by three arrays of that length: 16-bit frame thresholds, 8-bit texture indices, and 8-bit palette indices.
